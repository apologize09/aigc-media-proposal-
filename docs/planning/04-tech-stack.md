# 4. 技术栈与选型

## 4.1 选型原则

- 适合单个内部系统和一条主业务链路，不按多团队微服务来拆。
- 优先使用文档全、招人容易、后续一年仍好维护的组合。
- 长任务（分析、搜索、渲染快照）和页面请求分开，避免一次生成拖死页面。
- 模型和搜索已经固定为火山方舟上的 `doubao-seed-evolving` 及其 `web_search`。适配层只隔离方舟的响应格式，不表示本期可以换模型或另接搜索引擎。
- 草稿保存 GrapesJS 工程 JSON、来源和转存后的文件。不保存方舟原始响应。客户拿到的是导出的 HTML/CSS 和由此打印的 PDF。
- 有未确认规则的地方，用数据和校验留下扩展点，不引入规则引擎、工作流平台或低代码运行时。

## 4.2 推荐组合

这是在已确认目标下的选型，不再保留「实现时再二选一」。Q13 若明确改为只使用 Python，再整栈替换；在那之前按此实现。版本在开工时锁进仓库，不追 canary。运行时使用 2026 年 10 月的 Active LTS，即 Node.js 24。

| 层次 | 选择 | 对应的已确认目标 |
| --- | --- | --- |
| 语言 | TypeScript | 内部页面、模块结构、方舟响应和 worker 共用同一套类型 |
| 运行时 | Node.js 24 LTS | 一个语言覆盖 Web 和后台任务，不必为豆包再单开 Python 服务 |
| Web | Next.js App Router + React + TypeScript | 内部后台和客户只读链接在同一个系统里。分享页直接返回已冻结的 HTML 文件 |
| 后台界面 | Tailwind CSS + shadcn/ui | 只用于登录、列表、表单和对话框。客户提案不使用这套组件 |
| 提案编辑 | GrapesJS | 可视化编辑的基础。只在浏览器里加载，不参与服务端渲染 |
| 提案模板 | HTML/CSS 模板 | 每种模块一份 HTML 片段和共用样式。豆包填入内容，GrapesJS 在模板上改 |
| 提案导出 | 消毒后的 HTML/CSS，另由无头浏览器打成 PDF | 客户主交付仍是 HTML。PDF 使用同一份快照，不另做一版排版 |
| 模型 | 统一适配层，本期只有火山方舟 `doubao-seed-evolving` 一个实现 | 业务代码不直接拼方舟请求。适配层负责分析、生成和 `web_search` 结果提取。不接入第二家模型 |
| 接口 | 应用内的 HTTP API，页面与 worker 共用 `src/server` 函数 | 规划中的 API 清单已是 REST。worker 不绕 HTTP 调用自己 |
| 数据库 | PostgreSQL 16 + Prisma | 项目、成员隔离、快照、报价、任务、审核和会话都是关系数据。金额使用十进制，不用 JavaScript 浮点 |
| 异步任务 | Redis 7 + BullMQ，独立 worker | 豆包联网搜索和转存会超过页面请求时限。失败可查询、可重试，不覆盖已编辑草稿 |
| 文件 | S3 兼容对象存储，使用 `@aws-sdk/client-s3`。本地为 MinIO | 客户素材、转存案例和冻结 HTML 不进数据库。云厂商等 Q17，接口先按 S3 兼容写 |
| 登录 | 数据库会话 + HttpOnly、Secure Cookie。口令用 argon2id（`@node-rs/argon2`） | 管理员开通本地口令，无公开注册，无企业身份源。会话时长未配置时不按时间失效，所以不用自带固定过期时间的登录框架 |
| 结构校验 | Zod | 豆包返回的模块先校验再入库。校验失败不写入半截提案 |
| 部署 | Docker Compose + Nginx | Nginx 终止 TLS 并反向代理到 Web。后面是 Web、worker、PostgreSQL、Redis、对象存储。不使用 Kubernetes |
| 测试 | Vitest 做单元和接口测试，Playwright 做一条主路径 | 方舟用夹具。没有 API Key 时不把真实调用当作通过 |

不引入 LangChain、独立搜索服务、向量数据库、GraphQL、低代码平台和规则引擎。搜索已经由方舟 `web_search` 完成，这些组件不减少本期要写的模块渲染和转存逻辑。

### 建议的仓库形态

单包应用，而不是 monorepo。

```text
apps 和 packages 拆分先不做。
src/app          页面与路由
src/server       业务与适配器
src/worker       队列消费者
```

worker 与 web 共用 `src/server`，避免把领域逻辑复制两份。

## 4.3 已经可以定的技术决策

这些决策不依赖未提供的报价公式和组织架构。若审查否定某一条，对应章节要一起改。

### D1 编辑器保存 GrapesJS 工程，交付保存 HTML/CSS

客户要的是 HTML。GrapesJS 是编辑基础，但它的工程 JSON（组件、样式、traits）才是草稿源数据。发布时导出 HTML 与 CSS，消毒后写入对象存储。PDF 由这份 HTML/CSS 打印出来。

报价金额和素材 ID 放在组件 traits 里，不靠从自由 HTML 里反推。发布前用报价表和素材表重写对应节点，避免画布和内部数据分叉。整页源码模式不作为基础编辑方式。

### D2 搜索是适配器，不是爬虫

业务要求全网搜索图片、视频和创意案例。2026-10-16 第二批确定：不另接搜索引擎。`doubao-seed-evolving` 在生成提案模块时，通过火山方舟 Responses API 的 `web_search` 工具自行检索并匹配。

模型输出模块字段和它引用的来源，不输出作为源数据的整页 HTML。worker 只转存工具结果里出现的 http 或 https 地址，拒绝内网地址、链路本地地址和云主机元数据地址，并受大小与超时限制。模型写在正文里、但没有出现在工具结果中的地址，视为编造，不转存。

火山方舟把 `web_search` 描述为公开网页检索，不保证返回可下载视频。豆包搜索另有图片直搜接口，本期不接。没有媒体地址的结果以标题、摘要和来源进入模块，编辑可换成客户素材。授权状态默认未知。上传限制未配置时，转存被拒绝。

### D3 本期不计算利润率

Q5 已确认暂无公式：

- 成本项和报价项只保存人工录入的数量、单价和行金额。
- 不预置税率、币种、费率和利润率。
- 利润区对有财务可见的人员显示「未配置」，不返回比率。
- 模型不填写对外金额。科目名称建议仍是 R-A8，尚未单独点头。

### D4 长任务与页面分离

分析、搜索、整稿生成、单模块生成、发布渲染都进队列。HTTP 请求只负责入队和查询状态。worker 写库。页面轮询或刷新任务状态即可，MVP 不必上 WebSocket。

### D5 交付绑定快照

分享令牌指向快照 ID，不指向草稿。渲染文件和快照一起保留。应用回滚不会改写已经生成的 HTML 文件。

## 4.4 替代方案

| 方案 | 何时更合适 | 不作为默认的原因 |
| --- | --- | --- |
| 独立后端（NestJS）+ 独立 React 前端 | 已经有人专职维护 API，且短期会有第二个客户端 | 以当前范围，多一套服务和鉴权，收益不明显 |
| Python FastAPI + React | 团队主要写 Python，或生成链路会大量用 Python 生态 | 两门语言，提案编辑仍要在前端做。若确认团队只熟悉 Python，可以改选，数据模型和 API 清单仍适用 |
| 直接把模型 HTML 存进数据库，用代码编辑器改 | 看起来更「能编辑 HTML」 | 无法稳定替换一个案例或保证报价一致，安全面更大。与 D1 冲突 |
| Word/PPT 作为主交付，再附 HTML | 客户合同指定 Office | 与已确认的 HTML 交付冲突。可作为第二阶段导出，不替换主交付 |
| 无队列，请求里同步调用模型 | 希望少一个 Redis | 生成时长不可控，超时后用户无法判断是否写库。以这条链路的等待时间，队列是必要复杂度，不是多余组件 |
| Kubernetes、服务网格、独立搜索集群 | 多环境、多团队、弹性伸缩成为事实之后 | 当前规模用 Compose 或单机容器更易维护 |
| 低代码表单平台做内部端 | 只想先收集需求 | 做不到模块化提案渲染、快照和豆包联网搜索 |
| Drizzle 代替 Prisma | 团队要求迁移 SQL 全部手写 | 本期表关系多，Prisma 一种工具就够。不要两个 ORM 一起用 |
| Auth.js 等登录框架 | 要接企业微信、飞书或多种身份源 | Q12 已排除。会话时长还必须允许为空，框架默认的固定过期时间与 Q15 冲突 |
| LangChain 或方舟以外的 Agent 框架 | 需要编排多家模型和多家搜索 | 模型与搜索都已指定。多一层框架只会掩盖 `web_search` 的真实返回值 |

Q13 仍允许在开工前改用 Python。若改，FastAPI 加 React 可以承接同一套数据和 API，但 GrapesJS 仍在浏览器里，模板和适配层会拆开。未收到这个决定前，不按 Python 准备仓库。

## 4.5 主要技术风险

| 风险 | 影响 | 规划中的控制 | 仍需业务确认 |
| --- | --- | --- | --- |
| 网络案例的版权和平台条款 | 转存已经允许，但仍可能违反来源站点条款，也不能去掉水印或声称为自有案例 | 记录来源和授权状态；编辑可删除匹配；授权未知保持未知 | 来源站点清单仍待定 |
| 方舟联网搜索覆盖不了全部图片和视频文件 | 有的匹配只有网页，没有可转存的视频 | 不把缺失说成已找到素材；保留来源；允许手工补链后再转存 | 无。已确定不另接搜索引擎 |
| 转存失败或文件过大 | 选用后没有副本，提案里缺这张图 | 失败不改已有草稿；限制未配置时直接拒绝；编辑可改用客户素材 | 具体字节上限仍未给出 |
| 客户素材发往火山方舟 | 未公开创意会离开公司网络。这是已确认允许的 | 只从 worker 出站到方舟；没有 API Key 时任务失败，不更换模型 | 无。模型已定为豆包 Seed-Evolving |
| 模型输出不稳定 | 模块缺失或字段越界 | 结构校验失败即任务失败；不覆盖旧草稿 | 无，按此实现 |
| 长视频上传和播放 | 对象存储流量、浏览器播放兼容 | 原文件存储和基本播放。不转码。限制未配置则拒绝 | 具体大小和类型以后写入配置 |
| 提案版式被模块模型限制 | 个别客户要完全自由排版 | MVP 接受模板化专业版式；自由 HTML 放在第二阶段 P8 | 若第一期就必须自由排版，D1 要重审 |
| 以后补上利润公式 | 现在的「未配置」要换成真实计算 | 金额列已经按十进制保存，公式以后只加配置，不改历史快照里的对客报价 | 无。本期明确不算 |
| 单包 Next.js 把页面和任务耦在一起 | worker 误引入浏览器代码 | 约束：`src/server` 不引用客户端组件；构建时分开入口 | 工程规范，不是业务待确认 |
| 密钥进仓库或进前端包 | 搜索和模型额度被盗用 | 只放环境变量，服务端调用。见第 6 篇 | 无 |

没有把「换一家更强的模型」列为风险对策。质量问题先靠结构化校验、人工编辑和可重试解决。
