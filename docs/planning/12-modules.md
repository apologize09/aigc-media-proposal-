# 12. 模块拆分与具体需求

本文把已确认规划拆成可分别开发的模块。编号沿用第 2 篇的 M1–M25。后文若与第 3 篇的旧假设冲突，以第 9 篇对 R-A1 的改写为准：模型匹配可以进入草稿，客户链接仍要经过编辑和单人审核。

每个模块只写本期要做的事。第二阶段和明确不做的能力列在文末，不塞进模块必做项。

标记与第 1 篇相同：**已确认**、**合理假设**、**待确认**。待确认项不补默认数字、公式或品牌。

L 审计贯穿 A 之后的写操作

## 12.2 A 账号与权限

内部人员进入系统的唯一入口。客户不使用这个模块。

已确认：

- 管理员开通账号，使用本地口令。没有公开注册，不接企业身份源，不做多因素认证。
- 职责是管理员、方案编辑、审核人。一个人可以有多条职责。这组枚举名称是假设，职责种类已确认。
- 财务可见是开关，不是第四种角色。没有该开关的人不能查看或编辑成本、报价和利润。
- 管理员可见全部项目。其他账号只看见自己参与的项目。
- 没有要求禁止自己审核自己参与的项目。
- 停用账号后，旧会话不能再访问内部数据。
- 会话时长和锁定次数不写死。时长未配置时，会话不按时间失效，退出或停用才失效。锁定次数未配置则不锁定。

本期需求：

- 登录、退出、当前用户。错误口令不进入系统。
- 管理员可开通、改职责、改财务可见、停用。
- 内部接口无会话时拒绝。客户链接不使用这套会话。

待确认：无。具体小时数和锁定次数保持为空，直到环境变量写入数字。

不做：自助注册、单点登录、多因素认证、部门级或字段级权限（P11）。

## 12.3 B 客户与项目

一个客户需求对应一个项目，后面的素材、分析、提案、报价和任务都挂在项目上。

已确认：

- 可建立客户或品牌档案，并被项目引用。
- 可创建项目、打开项目、更新需求正文、归档。
- 成员关系就是隔离边界。非成员且非管理员看不见该项目。

本期需求：

- 客户最小字段：名称、联系人、邮箱、电话、内部备注。联系人字段可空。不假设客户编号规则。
- 项目最小字段：客户、标题、需求正文、负责人、归档时间。
- 添加和移除项目成员。
- 归档不撤销已发出的客户链接。

合理假设：项目状态名沿用第 3 篇状态机，确认前不把状态名写死成对外承诺。

待确认：客户扩展字段。没有确认前不加行业字段。

不做：线索、公海、营销自动化。

## 12.4 C 素材

保存客户提供的图片、视频和文档，以及后来转存的网络副本。

已确认：

- 需求文本和客户素材可以发往火山方舟。密钥只来自环境变量。
- `UPLOAD_MAX_BYTES` 或允许的 MIME 未配置时，上传和转存都拒绝。不写默认兆字节。
- 对象不能被公开列举。存储路径不由原始文件名决定。
- 被提案引用的素材不能直接删除。

本期需求：

- 上传、列表、经过权限检查的读取、删除。
- 记录来源类型、媒体类型、存储键、原始地址、文件名、MIME、大小、授权状态、署名。
- 客户上传的授权状态不自动写成已授权。网络转存默认「未知」。

待确认：具体 MIME 和字节数（Q10）。未给出之前，这个模块保持拒绝。

不做：视频抽镜头、听旁白（P10）、在线剪辑。

## 12.5 D 模型适配与队列

所有模型调用走这一层。业务模块不自己拼方舟请求。

已确认：

- 只使用火山方舟 Model ID `doubao-seed-evolving`。不在代码里改派到其他模型。
- 没有 API Key 时，分析和生成失败，不切换模型。
- 搜索不另接引擎，发生在生成提案的同一次调用里，使用方舟 `web_search`。
- 分析、生成、单模块重生成、转存是异步任务。状态为排队、执行中、成功、失败、取消。失败原因对操作者可见，可重试。
- 失败不删除已有草稿、素材和已选用案例。这是合理假设 R-A9，与「不写半截结果」一致，按此实现。

本期需求：

- 适配器三个动作：分析需求、生成提案初稿、重新生成一个 block。
- 从同一次响应里抽出 `web_search` 的查询、标题、摘要和真实 URL。
- worker 消费队列。CI 使用夹具，不访问真实方舟。

待确认：账号需开通 `web_search` 内容插件。API Key 已可注入；未开通联网搜索时生成任务失败（ToolNotOpen），分析不依赖搜索仍可执行。

不做：LangChain、第二家模型、自建搜索引擎、微调模型。

## 12.6 E 需求分析

把需求正文和素材元数据变成一份可改正、可确认的分析。

已确认：

- 输出结构固定为：摘要、目标、受众、交付说明、风格说明、约束、待澄清问题、检索提示。不按行业增加专有字段。
- 结构校验失败则任务失败，不写入半截分析。
- 提案生成使用已确认的分析版。未确认时给出明确状态，不悄悄使用过期分析。
- 模型不填写对外金额。

本期需求：

- 入队分析、查看当前版、改正未确认稿、确认。
- 同一项目最多一份当前分析。确认后仍保留版本号。

待确认：是否长期保存完整提示词（Q14）。本期审计不保存整份正文，项目本身不自动删除。

不做：按服务目录拆行业分析模板。

## 12.7 F 搜索与转存

在生成或重生成提案时，留下豆包真正搜到的案例，并把可下载地址收进本项目素材。

已确认：

- 每次工具调用保留查询、标题、摘要和来源地址。
- 只有工具实际返回的 URL 可以转存。模型正文里写出的图片或视频地址丢弃，不进入模块。
- 没有可下载地址时，保留带来源的文字参考。
- 编辑可以移除匹配，也可以手工补链后再转存。
- 授权状态默认未知，不显示成已获授权。授权状态只给编辑看，不写进客户 HTML。
- 网络案例保持外部参考，不称作公司案例。这是合理假设 R-A2。
- 转存要防 SSRF。限制未配置时转存失败。
- 转存未成功的媒体不能进入已发布快照。

本期需求：

- 查看某次生成留下的搜索记录。
- 从草稿模块移除一条匹配。
- 手工补链并入队转存。
- 选用后的副本写入素材表，并记下原始 URL。

已改写的假设：模型匹配可以直接进入草稿。不再要求先有一道单独的「选用」才能进草稿。进入客户链接之前仍要编辑和单人审核。

待确认：无额外搜索供应商。MIME 和字节数未配置时，本模块不能完成转存。

不做：第二套搜索 API、内部历史案例库（P4）、爬虫集群。

## 12.8 G 提案模板与发布

客户最终看到的 HTML 从这里导出。编辑器不直接充当客户页面。

已确认：

- 草稿源是 GrapesJS 工程 JSON，不是整页 HTML 字符串。
- 已确认章节：创意、案例、视觉风格、分镜参考、制作流程、报价、排期。
- 封面和「需求理解」是合理假设，建议放进本期。删掉它们不影响七类已确认内容。
- 发布冻结当时的工程 JSON、HTML、CSS，以及当时的对客报价副本。之后改草稿不影响该快照。
- 报价数字来自标记为对客可见的报价行。空报价显示「尚未填写对客报价」，不显示 0。
- 成本、利润、任务、内部备注、未放进模块的搜索痕迹不出现在客户 HTML。
- PDF 用同一份已发布 HTML/CSS 打印，不另做版式。客户主链接仍打开 HTML。
- 导出前去掉脚本。只保留段落、标题、列表、强调和 http/https 链接。

本期需求：

- `src/proposal/templates/` 中的中性 HTML/CSS 片段，注册为 block。
- 发布前用报价表和素材表重写 traits 里的报价行 ID 和素材 ID。
- 预览与发布使用同一套渲染。
- 快照只追加，不提供修改已发布内容的接口。
- 同一项目同时只有一个草稿。这是合理假设 R-A11。

待确认：品牌、logo、主色、对外公司名（Q16）。模板不编造公司名。七类模块是否允许整段删除（Q11），本期默认只做隐藏。

不做：整页源码模式（P8）、第二套 PDF 版式、把提案发到客户官网或广告账户。

## 12.9 H 可视化编辑

方案编辑在浏览器里改草稿。后台其他页面继续用 shadcn/ui。

已确认：

- GrapesJS 只在提案编辑页以客户端加载。
- 可改文案、排序、显示或隐藏、替换该模块引用的素材。
- 改一个模块不会把其他模块重置成重新生成的文本。
- 单模块重生成先放入任务结果，人确认后才写回。取消或失败时原模块不变。
- 已有草稿不会被生成任务自动覆盖，除非人明确选择替换。
- 替换素材时只能选本项目客户素材或已转存副本。
- 报价金额不能在画布里改。
- 保存使用更新时间做乐观锁。冲突时提示重新加载。不做实时协同。

本期需求：

- 编辑页、block 面板、素材替换、重生成确认。
- 接入前先做 Next.js 16 与 `@grapesjs/react` 的客户端探针，并确认只有一份 React。
- 使用开源 GrapesJS 与 `@grapesjs/react`。不使用 Studio SDK，不使用通用网页 preset，不使用编辑器 localStorage。

待确认：探针结果。未通过前不把编辑器写进页面。

不做：多人实时光标、整页粘贴外部 HTML。

## 12.10 I 成本、报价、利润

内部核算。客户页面只接收「对客可见」的报价行投影。

已确认：

- 成本项由人录入名称、数量、单价或金额、备注。
- 报价项由人录入，并选择是否进入提案。
- 金额使用十进制。币种可空。没有默认币种、汇率、税率。
- 只填总额时允许单价为空。数量和单价都有时，保存行金额。
- 没有利润公式。有财务可见的项目成员看到「未配置」，不返回利润率。其他人拒绝访问。
- 模型可以建议科目名称，不可以生成对外金额。这是合理假设 R-A8。
- 报价为空时仍可保存提案。送审不因利润拦截。这是合理假设 R-A12。

本期需求：

- 成本表和报价行的读取与整体保存。实现时只选一种写入方式，不同时做整表保存和行级接口。
- 利润接口固定返回未配置。
- 分享渲染测试确认不含成本备注。

待确认：无公式可确认。不要补一个临时毛利率。

不做：合同、开票、回款、折扣审批、历史报价区间建议（P5）。

## 12.11 J 执行任务

审核通过后可以执行的任务清单。全部由人创建。

已确认：

- 手工新增、修改、确认、取消。
- 可保存负责人、状态、开始和结束日期。日期可空。
- 不按行业或服务类型自动生成任务。
- 客户 HTML 不含任务。

本期需求：

- 状态只做草稿、已确认、取消。
- 任务可以在快照存在后记下所属快照。没有快照时也能先记在项目上。
- 不建任务依赖图，不记工时。

待确认：是否要跟踪进行中、完成、前置依赖和工时（Q9）。未答复前不加这些字段。

不做：行业任务包（P3）、通知和 @（P6）。

## 12.12 K 审核与客户链接

正式交付只发生在审核通过之后。

已确认：

- 送审对象是快照。审核结论不改写草稿正文。
- 一名审核人通过即视为该快照通过。退回和再次通过都保留记录。不做会签。
- 未通过不能交付。草稿再改之后，旧的通过不能交付新内容。
- 客户没有账号，只打开链接。
- 链接可以撤销。未被撤销的旧链接继续打开创建时的快照。
- 不强制过期，不设置访问口令。归档不自动撤销。
- 明文令牌只在创建时返回一次，库里保存哈希。
- 令牌错误、已撤销或已过期时，不返回提案内容，也不提示它曾经属于哪个客户。

本期需求：

- 送审、通过、退回、创建链接、撤销链接。
- `GET /p/:token` 返回冻结 HTML，不加载 GrapesJS。
- PDF 作为该快照的附加打印，不是客户主页面。

待确认：无强制有效期。若以后要过期，再写入可空的到期时间，不现在补一个默认天数。

不做：客户批注和在线确认（P1）、版本差异对比视图（P7）。

## 12.13 L 审计

管理员按项目查看谁在什么时间改了关键对象。

已确认：

- 至少记录发布、审核、交付、报价变更、权限变更。
- 记录包含操作者、时间、对象。
- 记录里不写密钥、口令、完整分享令牌。

本期需求：

- 追加写入，不提供修改审计记录的接口。
- 管理员可见全部项目的审计。审计正文不保存整份提案或提示词。

待确认：提示词和素材保留多久（Q14）。本期不自动删除。

## 12.14 不属于本期模块

第二阶段，确认有使用需求后再单独立项：客户账号与批注、多套创意方向、行业模板、历史案例库、报价区间建议、通知、版本对比、整页源码、视频内容理解、更细的数据权限。

明确不做：自建搜索或爬虫、训练模型、在线剪辑、合同开票回款、完整 CRM、原生 App 或小程序、多租户 SaaS、实时协同、自动投放到客户官网或广告账户、向量检索、历史方案导入（Q18，未要求前不做）。

## 12.15 模块之间不许打破的约束

- 报价只有一份数据：报价表。画布和客户 HTML 都只投影对客行。
- 素材只有一份数据：素材表。画布 traits 只保存素材 ID。
- 客户链接只读快照文件，不重新调用模型和编辑器。
- 搜索只有方舟 `web_search` 这一条路径。
- 利润区在公式出现之前保持「未配置」。
