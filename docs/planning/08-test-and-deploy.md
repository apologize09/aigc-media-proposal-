# 8. 测试、部署、环境变量与回滚

## 8.1 测试策略

测试保护的是不变量，而不是把规划文档再抄一遍。供应商用夹具和契约测试，CI 不调用付费 API，也不访问真实客户素材。

| 层次 | 测什么 | 工具建议 |
| --- | --- | --- |
| 单元 | 渲染与消毒、报价行金额、利润在「有公式配置」与「未配置」两种返回、令牌哈希、权限判断纯函数、模块校验 | 与 TypeScript 配套的测试运行器（Vitest 即可） |
| 集成 | API + 测试数据库 + 本地对象存储。覆盖登录、越权、上传、发布事务、审核拒绝交付 | 同一测试运行器，数据库用迁移起一个空库 |
| 契约 | 模型适配器：合法 JSON 入库、缺字段失败、多出来的金额字段被丢弃 | 固定夹具，无网络 |
| 端到端 | 第 8.2 节的少数全路径 | Playwright |
| 不测 | 搜索引擎是否真的「全网」、模型文案好不好、视觉是否好看 | 文案质量靠人工预览，不写成自动化断言 |

数据库测试互相隔离，不用开发库。对象存储使用单独的测试桶。

## 8.2 必须自动化的不变量

这些断言对应已确认规则或已采用的技术决策。假设被推翻时，先改断言再改实现。

1. 未登录请求内部 API，被拒绝。
2. 无财务可见时读取利润和成本被拒绝；同一用户仍可预览含对客报价的提案。非项目成员且非管理员读取该项目被拒绝。
3. 渲染输入夹带成本、利润、任务、内部备注时，输出 HTML 不包含这些字符串。用带特征前缀的测试数据，避免误伤正常文案。
4. 未选用的搜索候选不出现在渲染输出。
5. 模型输出无法通过校验时，分析的当前版不变。
6. 已有草稿时，生成任务在未明示替换的情况下不改模块正文。
7. 发布成功后修改草稿，快照存储中的 HTML 不变。
8. 快照没有通过记录时，创建交付失败。
9. 通过之后草稿又更新时，用旧通过记录为新内容创建交付失败。
10. 撤销后的令牌访问阅读页，得到 404，响应体不含项目标题。
11. 令牌 A 不能读出另一个快照的 HTML。
12. 乐观锁：过期的 `updated_at` 不能写回模块。
13. 脚本片段和 `javascript:` 链接不能出现在渲染结果的可执行位置。
14. 利润接口返回未配置，不返回比率。
15. 被提案引用的素材删除请求被拒绝。
16. 上传限制未配置时，上传和转存都被拒绝。
17. 一名审核人通过后可以创建交付；第二名审核人不是前置条件。
18. 新快照交付后，旧令牌仍返回旧 HTML。撤销只影响被撤销的那条链接。

端到端只保留一条主路径加两条失败路径，避免把全部不变量都点进浏览器：

- 主路径：登录 → 建项目 → 上传夹具素材 → 用夹具完成分析确认 → 选用一条夹具案例 → 编辑一个模块 → 填写一条对客报价 → 发布 → 通过 → 打开分享页能看见该模块和报价。
- 失败路径：非法模型输出后页面仍显示上一次确认的分析。
- 失败路径：退回后分享页仍是上一份已交付快照，而不是退回后的草稿。

## 8.3 CI

每次合并前运行：lint、类型检查、单元测试、集成测试。端到端在主路径稳定后作为同一流水线的后续作业。

CI 环境变量使用流水线密钥注入测试用的假值。不把 `.env` 提交进仓库。搜索和模型基地址指向测试夹具服务器或适配器的假实现，不指向生产。

## 8.4 部署方案

目标规模是一个内部系统：Nginx、一个 Web 进程、一个 worker 进程、PostgreSQL、Redis、对象存储。

```text
Nginx（TLS，唯一公网入口）
    └─ Web
仅内网：PostgreSQL、Redis
Worker（无公网入口）
    ├─ PostgreSQL、Redis、对象存储
    ├─ 火山方舟出站
    └─ 无头浏览器，把已发布 HTML/CSS 打成 PDF

对象存储可为同一台机器上的 MinIO，或云厂商的桶。生产建议用云厂商的桶，避免和数据库抢同一块磁盘。最终放在哪等 Q17。
```

Nginx 只做 TLS、转发和请求体大小。`client_max_body_size` 不写一个业务默认兆字节。`UPLOAD_MAX_BYTES` 未配置时，把它设为拒绝上传请求的极小值，与「未配置则拒绝上传」一致。配置了该变量之后，Nginx 的上限与它相同。上传类型仍由应用判断。

环境：

| 环境 | 用途 |
| --- | --- |
| 本地 | Compose。MinIO、Postgres、Redis 都在本机 |
| 预发 | 与生产相同的进程拓扑和迁移方式，独立库、独立桶、独立供应商密钥（可以用低额度）。用脱敏或虚构数据 |
| 生产 | 真实客户素材和密钥。不在生产库上试迁移 |

不使用 Kubernetes，除非 Q17 的现有平台已经是 Kubernetes。不要为这个系统新建集群。

### 发布步骤

1. 构建带版本号的不可变镜像。版本号即 Git 提交。
2. 对生产数据库做备份（第 8.6 节）并确认备份可定位。
3. 在预发对生产备份的副本演练迁移（至少在第一次上线和每次改表时）。
4. 对生产执行迁移。迁移只做兼容变更：加表、加可空列、加索引。禁止在同一次发布里删除仍被旧版本读取的列。
5. 启动新的 worker，再切换 Web 流量。worker 先升级，是因为新 Web 可能入队旧 worker 不认识的任务；更稳的约定是：**任务名只增不改，旧 worker 遇到未知任务会保留在队列里**。若做不到，就在切换窗口停止入队。
6. 检查 `/api/health`、登录、打开一份已知快照的分享页。
7. 观察新产生的 ai_job 能结束（成功或可理解的失败），而不是一直停在 running。

分享页读的是对象存储里的 HTML，不在发布时重渲染历史快照。因此应用升级不应改变已交付文件。

## 8.5 环境变量

`.env.example` 在 T1 建立。下表是清单。值为空。没有出现的业务数字不要偷偷加一个默认税率或默认毛利率。

| 变量 | 使用方 | 说明 |
| --- | --- | --- |
| `DATABASE_URL` | web, worker | PostgreSQL |
| `REDIS_URL` | web, worker | 队列 |
| `AUTH_SECRET` | web | 会话签名 |
| `APP_BASE_URL` | web | 生成分享链接的对外源 |
| `S3_ENDPOINT` | web, worker | |
| `S3_REGION` | web, worker | 供应商不需要时也保留键，避免代码分叉 |
| `S3_BUCKET` | web, worker | |
| `S3_ACCESS_KEY` | web, worker | |
| `S3_SECRET_KEY` | web, worker | |
| `AI_PROVIDER` | worker | 固定为 `volcengine-ark` |
| `AI_BASE_URL` | worker | 火山方舟地址，默认文档中的 `https://ark.cn-beijing.volces.com/api/v3`。这是供应商地址，不是业务默认上限 |
| `AI_API_KEY` | worker | 空则分析和生成失败。不写入仓库 |
| `AI_MODEL` | worker | 固定为 `doubao-seed-evolving` |
| `AI_ALLOW_ASSET_UPLOAD` | worker | 已确认允许出域。未设置时按允许发送。设为 `false` 时只发送文本 |
| `UPLOAD_MAX_BYTES` | web, worker | 未设置时拒绝上传和转存，并提示未配置。不写默认兆字节 |
| `UPLOAD_ALLOWED_MIME` | web, worker | 未设置时同样拒绝。逗号分隔。具体列表仍待填写 |
| `SHARE_DEFAULT_TTL_HOURS` | web | 留空。已确认不强制过期；链接靠撤销失效 |
| `AUTH_SESSION_TTL_HOURS` | web | 留空。留空时会话不按时间失效。写入数字后才按该数字失效。代码不写死小时数 |
| `AUTH_LOCKOUT_THRESHOLD` | web | 留空。留空时不做锁定。写入数字后才锁定。代码不写死次数 |
| `LOG_LEVEL` | web, worker | |
| `TRUST_PROXY` | web | 置于 Nginx 之后时开启，用于识别原协议和来源 |

Web 进程不需要 `AI_API_KEY`。搜索使用同一次方舟调用，不再单独配置搜索密钥。前端打包环境不注入任何密钥。

## 8.6 备份

- PostgreSQL：发布前逻辑备份或平台快照。保留周期等 Q14。在周期确定前，至少保留最近一次发布前备份，直到下一次发布成功。
- 对象存储：开启桶的版本化或等价能力，使误删 HTML 和素材可恢复。若平台没有版本化，发布文档里写明当前做不到，不假装能恢复。
- 备份与生产同等访问控制。不把备份下载到个人电脑作为流程的一环。

## 8.7 回滚

### 应用回滚

1. 将 Web 和 worker 切回上一枚镜像。
2. 不重渲染已有快照。
3. 验证：上一版本页面可登录，已交付令牌仍可打开旧 HTML。

前提是这次发布没有做不兼容迁移。若新版本已经写入新任务名，旧 worker 必须能安全忽略未知任务（留在队列），而不是崩溃重启循环。这条作为 T16 的演练项。

### 数据回滚

- 优先向前修复。生产不把数据库整库倒回，除非发布造成数据损坏且已停止写入。
- 整库恢复会丢掉恢复点之后的新项目和审核记录。只有在确认停止写入并通知使用方之后，才从发布前备份恢复。
- 对象存储用版本化恢复单个键，不整桶覆盖。
- 已交付 HTML 若内容错误，处理方式是新版本、重新单人审核、新链接。旧链接继续指向旧文件。不改历史文件。

### 迁移失败

- 迁移脚本失败则停止发布，不切换流量。
- 每次迁移放在事务中（PostgreSQL 支持的 DDL）。无法放进事务的操作拆成单独发布。
- 不在同一版本中执行「加列」和「删旧列」。删列最早属于后续一个已观察过的版本。

### 供应商故障时的降级

模型和搜索不可用时，录入、编辑、报价、对已发布快照的审核和分享仍可用。页面显示任务失败原因。不自动把失败变成空提案去覆盖草稿。

## 8.8 配置未齐时的行为

下列情况允许系统启动，但相关功能明确失败，避免用默默的默认值运行：

- 无 `AI_API_KEY`：分析和带搜索的生成失败，原因为未配置。不改用别的模型。
- 模型 ID 不是 `doubao-seed-evolving` 的部署视为配置错误，任务不执行。
- 利润：按 Q5 显示未配置。
- 无 `UPLOAD_MAX_BYTES` 或无 `UPLOAD_ALLOWED_MIME`：拒绝上传和转存。

数据库、Redis、`AUTH_SECRET`、对象存储缺失时，Web 不应进入可登录状态。健康检查失败，流量不切过来。
